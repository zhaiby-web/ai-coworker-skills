# 场景示例集 · Worked Examples

## 1. 阶段错配拦截
用户：「方向还没定，但下周要给客户看，帮我搭个 React 原型，显得专业。」
合格执行：指出"方向未定上 React = 过早工程化，改方向的成本会惩罚你"；改做 HTML 多页原型（快、改起来便宜）；同时留台阶——「如果其实是方向已定的正式演示，告诉我，我直接按工程底线重建 React Mock」。

## 2. 机械转换拦截
用户：「把这个 HTML 原型转成 React 工程。」
合格执行：不逐标签翻译。读 HTML 当设计参照 → 重新设计：组件拆分、`services/api.ts + mockApi + realApi` 三层、六态覆盖（成功/失败/空/无权限/加载/超时）、类型定义 → 交付时三声明（回答什么/不回答什么/不能合入上线）。

## 3. 原型想"转正"时
用户：「演示效果不错，就在这个基础上直接上线吧。」
合格执行：重申准入门禁——原型故意跳过了正式工程的所有关卡（仓库、契约、权限、验收）；给出"原型→正式工程"的移交清单，而不是把原型 push 进正式仓。

## 4. 接手来历不明的原型
用户扔来一个旧原型目录：「接着往下做。」
合格执行：先盘点再动手——哪个版本、哪些是 mock、有没有写死的数据和假接口；盘点结果决定是延用、重建还是先补交付文档。
