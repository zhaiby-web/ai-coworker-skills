# Prototype Prompt Templates

四套可直接复制的提示词模板。方括号内容按实际任务填写。

## 1. 生成 HTML 原型

```text
你是产品原型设计助手。

请基于以下产品目标生成一个静态 HTML 原型：
1. 只用于探索期评审，不作为正式前端代码。
2. 原型应能直接用浏览器打开。
3. 重点表达页面结构、信息层级、主流程、关键状态。
4. 可以使用 mock 数据，但不要把 mock 字段描述成正式接口字段。
5. 不要包含真实客户敏感数据、token、cookie、header。
6. 输出后请说明：这个原型解决了什么问题，哪些内容仍需产品确认，哪些内容不能直接进入正式研发。

产品目标：
[填写产品目标]

核心用户：
[填写用户角色]

核心流程：
[填写流程]
```

## 2. 从 HTML 原型重建 React Mock 原型

```text
你是 React Mock 原型开发助手。

请读取以下材料：
1. HTML 原型文件：[填写路径]
2. 产品交付文档：[填写路径]
3. 当前设计基线：[填写路径]

请不要机械复制 HTML 结构，而是重新设计 React Mock 工程：
1. 拆分页面、组件、状态和 mock 数据。
2. 建立 services/api.ts、mockApi.ts、realApi.ts。
3. 页面统一调用 api 层，不直接写死 mock 数据。
4. 覆盖成功、失败、空态、权限不足、加载中、超时等状态。
5. 输出组件清单、接口契约草案、mock 场景清单。
6. 明确说明该工程是原型，不是正式仓库代码。

禁止事项：
1. 不要写入正式业务仓库。
2. 不要引入真实 token、cookie、header。
3. 不要把 HTML 原型字段直接当正式接口字段。
4. 不要声明可以直接上线或直接合入。
```

## 3. 直接创建 React Mock 原型

```text
你是 React Mock 原型开发助手。

本次目标是直接创建一个可运行的 React Mock 原型工程，用于产品评审、客户演示、接口契约讨论和研发拆解，不是正式业务仓库代码。

请先基于以下输入进行设计：

产品目标：
[填写产品目标]

目标用户：
[填写用户角色，例如产品经理、运营、研发、QA、客户管理员]

核心业务场景：
[填写场景]

核心页面：
[填写页面清单，例如列表页、详情页、配置页、权限态页面]

关键流程：
[填写用户从进入页面到完成任务的主要路径]

必须覆盖的状态：
[填写成功、失败、空数据、权限不足、加载中、接口超时等]

请按以下步骤执行：

1. 先输出产品理解摘要，说明本原型要验证什么，不验证什么。
2. 输出页面结构和组件拆分方案。
3. 输出 mock 数据模型和接口契约草案。
4. 创建 React Mock 工程，优先使用 React + TypeScript + Vite。
5. 建立统一 API 层，至少包含 services/api.ts、services/mockApi.ts、services/realApi.ts。
6. 页面只能调用 services/api.ts，不得直接写死 mock 数据。
7. mock 数据放在 mocks/ 或 services/mockApi.ts，并覆盖多种业务状态。
8. 页面要包含必要的空态、错误态、权限态、加载态。
9. 交付后说明如何启动、如何切换 mock / real API、哪些字段仍待正式接口确认。

推荐工程结构：

src/
  pages/
    [PageName]/
      index.tsx
      components/
      hooks/
      types.ts
  services/
    api.ts
    mockApi.ts
    realApi.ts
  mocks/
    data.ts
    scenarios.ts
  components/
  styles/

交互要求：

1. 主要按钮、筛选、页签、详情、展开收起应可点击。
2. 列表和详情应由 mock API 返回，而不是写死在 JSX 中。
3. 需要能模拟接口失败、空数据和权限不足。
4. 演示模式下不得展示真实客户名称、证件号、token、cookie、header、原始请求体。
5. 涉及敏感诊断或内部链路时，只展示脱敏摘要。

输出要求：

1. 给出本次生成或修改的文件清单。
2. 给出本地启动命令。
3. 给出 mock 场景清单。
4. 给出后续切真实接口前必须确认的问题。
5. 明确声明：这是 React Mock 原型，不是正式工程代码，不能直接合入、上线或替代正式研发流程。

禁止事项：

1. 不要写入正式业务代码仓库，除非用户明确指定并完成开发准入确认。
2. 不要使用真实 token、cookie、header、登录态、客户敏感数据。
3. 不要把 mock 字段自动视为正式接口字段。
4. 不要把原型中的按钮行为视为正式可执行动作。
5. 不要声明"已可上线""已可发布""可直接合入"。
```

## 4. 判断该用哪种原型

```text
你是产品经理的 AI 开发教练。

请根据以下信息判断本次应该使用 HTML 原型、React Mock 原型，还是先写产品方案文档：

业务阶段：
[探索期 / 方案收敛期 / 售前演示 / 开发准备期]

不确定点：
[产品形态 / 用户路径 / 页面布局 / 接口字段 / 权限 / 技术实现]

目标对象：
[客户 / 内部产品评审 / 研发 / QA / 售前]

输出要求：
1. 先给一句话结论。
2. 说明为什么选这种方式。
3. 说明不适合的方式为什么不选。
4. 给出下一步产物清单。
5. 标明哪些内容不能进入正式研发。
```
