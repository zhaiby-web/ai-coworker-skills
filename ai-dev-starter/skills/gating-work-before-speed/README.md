# 小白指挥AI开发之怎么开工

> Gating Work Before Speed — boundaries before velocity.

治"AI 一听'直接开干'就真的直接开干"：动手写代码前先过**五问**（用什么契约？什么数据源？改哪一层？怎么证明？不能做什么？），锁定正式仓库/分支/基线，**commit→push→建MR 逐级授权**（说了"顺手提交"也只授权到 commit 这一级）；改到共享代码立即暂停上报。与 TDD 等实现方法论是组合关系：门禁管"能不能开工、在哪开工"，方法论管"怎么写"。

## 何时用
- 让 AI 在 git 仓库里加功能、改代码、修 bug 之前
- 说了"直接开干/写完顺手提交"——这句话恰恰最需要把授权拆开
- AI 干着干着改到了公共组件/别人的代码

**触发例句**：「帮我加个功能，直接开干」「改这个 bug，写完提交」「它是不是乱改我代码了」

## 何时不用
- 纯阅读、分析、方案设计（不写实现代码就没有开工门禁）
- 明确标注"丢弃式"的沙盒实验（但产物仍不得混入正式仓库）

## 安装
SkillHub 页面直接安装，或拷贝本目录到 `~/.claude/skills/` 或 `~/.codex/skills/`。建议在全局指令钉常驻规则（见技能包主页），因为"顺手一改"的场景靠被动触发会漏。
