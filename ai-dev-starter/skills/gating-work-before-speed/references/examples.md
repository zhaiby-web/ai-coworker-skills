# 场景示例集 · Worked Examples

## 1. "直接开干"的正确打开
指令：「加一个配置读取功能，直接开干，写完顺手提交。」
合格执行：先答五问并落档（契约=现有配置格式；数据源=仓内真实文件；改哪层=新增 config 模块不动共享代码；证明=单测+运行输出；禁止=push/建MR 未授权）→ 跑基线命令（branch/status/HEAD）→ 实现 → 仅执行到 commit 一级。"顺手提交"授权的是 commit，不是 push。

## 2. 侵入性暂停
干到一半发现最优解要改公共函数 `formatAmount`。
合格执行：暂停，上报：「这一步会改多处共用的代码，影响所有调用方。方案A：改共享函数（动静大）；方案B：本模块内包一层（零侵入）。推荐B。你定。」——不许"顺手就改了"。

## 3. 中途加需求重新过门
用户中途说「顺便把 X 也改了」。
合格执行：X 重新过五问（尤其"改哪层"和"禁止事项"），不因主任务已过门而豁免——新范围新门票。

## 4. 紧急修复的最小门
线上急修压力下，五问压缩为两问底线：基线对不对（改的是不是正确分支）+ 禁止清单在不在（不许顺手重构）。门可以压到最小，不能压到零，且报告里写明省了哪几问。

## 5. 没有 git 的场景
写一个一次性脚本、没有仓库。
合格执行：战场锁定豁免（无仓可锁），但五问的轻量版仍答：目标、数据源、产出位置、怎么验证、不碰什么——并说明"本次无版本控制，产物不可回滚"。
