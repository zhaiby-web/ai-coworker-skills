# 场景示例集 · Worked Examples

## 1. 新人第一周（完整包）
见 SKILL.md 正文 Example：一个目标（开通流程页）拆成骨架卡/mock API 卡/调查卡，语义决策全留总控侧。配套要点：**卡里引用的契约必须先定稿**——"周一给契约、周二给草图"是发卡人的作业，契约没定稿的卡不能发。

## 2. 调查类任务卡
「盘点现有系统的开通入口。负责：列出清单（路径/触发条件/所属模块，表格）。不负责：判断哪些该保留。验收：每行有源码位置佐证。」——调查卡的关键是把"查"和"判"切开：查的产出是表格，判留在懂业务的一侧。

## 3. 一张坏卡的诊断
坏卡：「实现会员等级模块，具体规则你看着办。」
病灶：「看着办」= 把语义判断塞给了低上下文执行者，必产出自信的错误答案。
拆法：等级规则（判断）→ 发卡人先定成输入契约；卡只剩「按附表规则实现计算函数，规则表之外的情况一律抛出待定异常并回报」。

## 4. 执行者越界了
回执显示执行者"顺手"改了不负责范围里的公共样式。
合格处理：按越界协议裁决（已披露+纯增量+更保守+不跨界+不碰线上 → 可追认；否则回退）——不静默合并。配合「验收神器」技能使用效果最佳。

## 5. 反复被问同类问题
执行者第三次问"金额保留几位小数"。
信号：不是执行者笨，是卡模板缺了「数据格式」栏——修模板，别修人。
