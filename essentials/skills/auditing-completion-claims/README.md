# 小白指挥AI干活之验收神器

> Auditing Completion Claims — "it says done" never silently becomes "it is done."

任何"完成了/做好了/通过了/环境好了/已发布"，先别信：能查机器事实的先查，查不到的追问四件事——**完成了什么？怎么证明？还缺什么？谁接下一步？**证据分五级（E1文件写明→E5你可拍板），推断永远不许冒充已验证。

## 何时用
- AI 汇报"做完了/测试通过了/环境好了"，你想知道到底完成到哪一层
- 你转述别人的结论（"研发说改完了"），需要帮你核实再接受
- 自己要宣布完成前的自检

**触发例句**：「它说部署好了，你帮我确认下」「这个'通过了'可信吗」「验收一下这份回执」

## 何时不用
- 你以自己的直接权限拍板的事（产品决策，凭你一句话即成立，不用审）
- 纯观点讨论，没有完成声明
- 你明确说"先记下、别验证"

## 安装
SkillHub 页面直接安装，或拷贝本目录到 `~/.claude/skills/` 或 `~/.codex/skills/`。零依赖、纯提示词。
建议在全局指令（`~/.claude/CLAUDE.md` / `~/.codex/AGENTS.md`）钉一条常驻规则让它每次必查——见技能包主页说明。


> 兼容性：适配 Claude Code、Codex 及任何支持 SKILL.md 规范的平台。包内 `agents/openai.yaml` 仅为 Codex 侧的显示名配置文件，**不调用任何 OpenAI 接口、零网络依赖**。

## FAQ（来自作者自己踩过的坑）

**Q: AI 说"测试通过了"，我又看不懂代码，追问不就是让它把话再说一遍吗？**
A: 不问"对不对"，问四件事：完成了什么、怎么证明（要命令和输出，不要复述）、还缺什么、谁接下一步——再问一句"这个通过是哪一层的通过"（单测≠冒烟≠共享环境≠用户场景）。你不需要懂代码，只需要看它能不能把证据摆出来。

**Q: 它明明跑了命令验证过，怎么还会错？**
A: 命令只忠实报告"它查的那个对象"的状态——而那个对象可能是过期快照（比如没 fetch 的本地 master）。所以结论要带坐标和新鲜度：查的哪个仓、哪个 SHA、刚 fetch 的还是仅本地。作者被这个坑翻过车，才有了这条规则。

**Q: 装了之后有时候不触发，还是回"收到"怎么办？**
A: 常驻行为类技能靠描述被动匹配天然会漏（作者实测三轮才发现）。把安装说明里那条常驻规则钉进你的全局指令文件，一劳永逸。
