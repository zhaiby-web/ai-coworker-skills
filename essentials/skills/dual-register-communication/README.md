# 小白指挥AI干活之让AI讲人话

> Dual Register Communication — plain language for you, full rigor for artifacts.

治一个两难：说"请讲人话"，AI 把派工单和技术文档也写成大白话；不说，汇报满屏术语看不懂。本技能按**输出通道**分语域——跟你说话用业务白话（先结论后原因、术语首次必解释、ID/字段名等锚点原文保留），写文档保持技术严谨（禁止白话稀释）；请你拍板的问题固定四件套：白话背景+白话选项+推荐+一句理由。

## 何时用
- AI 的汇报你看不懂，想让它说人话，但又怕文档跟着变水
- 会话既要向你解释、又要产出派工单/技术方案/代码
- AI 抛给你的"决策问题"里全是术语，没法判断

**触发例句**：「用我能听懂的话解释，然后写一份技术方案」「说人话」「这个问题你用白话重新问我一遍」

## 何时不用
- 全技术受众的会话（大家都懂行，直接技术语域效率最高）
- 产出物本来就该是白话（营销文案、用户帮助文档——那是"产品文案第三通道"，规则不同）

## FAQ（来自作者自己踩过的坑）

**Q: 我说了"说人话"，结果它把派工单也写成大白话了，怎么办？**
A: 这正是本技能治的病：语域跟输出通道走，不跟会话走——"说人话"只管跟你汇报的通道，文档照旧严谨。装了还发生，检查是不是在文档要求里也写了"用白话"。

**Q: 为什么有的词它不翻译，直接甩原文给我？**
A: 那是锚点（字段名、配置项、任务编号）——保留原文是故意的，让你能一字不差拿去问研发。翻译了反而断了对质链路。白话负责包在锚点外面解释它。

**Q: 每个术语都解释一遍，会不会很啰嗦？**
A: 只在首次出现时解释；你自己主动用过的词会被记为"已知"不再解释。觉得啰嗦可以直接说"这些词我都懂"。
